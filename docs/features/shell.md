# The frame, the Overview and the Kubernetes summary

The behaviour of the app frame, the Overview and the session that feeds them, moved from [AGENTS.md](../../AGENTS.md) unchanged apart from its link paths: the three paragraphs starting "The frame (`desktop/shell/`)…", "Overview derives its cards…" and "The Kubernetes summary session…".

Code:

- `crates/freshkube-desktop/src/desktop/shell/` is the frame: `header.rs`, `rail.rs`, `column.rs`, `source.rs`, `chrome.rs`, `frame.rs`; the settings pages are `desktop/settings/`, the switch is `desktop/switch.rs`.
- `crates/freshkube-desktop/src/presentation/` derives the Overview's cards (`overview/`) and Attention (`attention/`).
- `crates/freshkube-core/src/kubernetes_summary/` is the session; `crates/freshkube-desktop/src/desktop/kubernetes_summary/` hands it to the shell.

Tests that prove it (the files with a `#[test]`, `#[tokio::test]` or `#[gpui_kit::test]`, found with `git grep -l '#\[test\]\|#\[tokio::test\]\|#\[gpui_kit::test\]'` run over `desktop/shell/`, `desktop/tests/`, `desktop/settings/`, `presentation/`, `desktop/kubernetes_summary/` and core's `kubernetes_summary/`):

- The frame, `crates/freshkube-desktop/src/desktop/`: `tests/{chrome,column,custom,header,keys,kubernetes_only,layout,motion,observability,operations,overview,rail,screens,services,settings,shells,status,target}.rs`; inline tests in `shell/{column_state,context,fps,rail}.rs`; `switch_tests.rs`, `link_tests.rs`, `object_links/tests.rs`, `search/tests.rs`, `startup/tests.rs`, `settings/tests.rs`, `settings/edit_tests.rs`, `settings/destinations/tests.rs`, `settings/sources/tests.rs`.
- The Overview, `crates/freshkube-desktop/src/presentation/`: `tests.rs`, `attention/tests.rs`.
- The summary session: `crates/freshkube-desktop/src/desktop/kubernetes_summary/tests.rs`; core's `crates/freshkube-core/src/kubernetes_summary/`: `session_tests.rs`, `driver_tests.rs`; inline tests in `driver.rs`, `mod.rs`, `observation.rs`, `project.rs`, `requests.rs`, `retained.rs`, `session.rs`, `summarize.rs`.

The frame (`desktop/shell/`) is a 44 dp header, a 64 dp icon rail, a 208 dp column for the rail's area and a 28 dp status bar ([docs/DESIGN.md](../DESIGN.md)). The dock, when it has tabs, sits in the page cell under the page, as a cached view with an explicit height; `freshkube_ui::page::set_below` tells pages the room it takes. The rail's areas (`Area` in `desktop/pages.rs`) are Overview, Nodes, Namespaces, Events, Applications, Monitoring and Observability; the six Kubernetes groups and Custom Resources; and Control plane. The groups, Custom Resources, Control plane, Monitoring, Observability and Applications have a column: a group's kinds (Health first under Workloads), the API groups, the Talos pages, the dashboards, the destinations, or the applications. A group's rail button reopens its last kind. Its problem dots (`RailMarks`) are derived with the Overview's cards. `screens::page_width` subtracts the rail and, when shown, the column. Where the shell is (the page, the area, the kind memory, the column and rail scroll state) lives in `shell::Navigation` (`shell/navigation.rs`), which `Pilot` owns as `navigation`. What the frame shows beside the page (the cached header, rail and column, the countdown, the fps readout, the forwards indicator, the appearance and the app menu's state) lives in `shell::Chrome` (`shell/chrome.rs`), which `Pilot` owns as `chrome`; it follows the system's appearance itself, from `Chrome::new`. `Pilot::new` composes the shell from these owners, the page map (`page_map::Pages::new`, `desktop/page_map.rs`) and the session's fields (`Pilot::with_session`), then starts it (`Pilot::start`) ([ARCHITECTURE.md](../ARCHITECTURE.md#what-a-page-is)). The shell hears every page's events from one `Pilot::subscribe_page_events` ([ARCHITECTURE.md](../ARCHITECTURE.md#how-a-page-reaches-the-shell)). Command-1 through Command-9 follow Overview, Nodes, Namespaces, Events, Health, etcd, System services, Security and Lifecycle; Control-Tab also visits the last other kind. Kubernetes-only mode starts on Overview, and its Control plane column offers a talosconfig instead. Node inspection and service logs live in the node pane; the header holds the context switcher (its Clusters list opens an entry of `workspace.json` through `desktop/switch.rs`, parking the one left; [ACCESS_IDENTITY.md](../ACCESS_IDENTITY.md#the-session-registry) has what a switch does to each thing), the location, Search everything, Refresh and Settings, which holds the app version and a Workspace row that opens the Settings page (`Page::Settings`, `desktop/settings/`), a table of the clusters in `workspace.json` that Add, Edit, Remove and Move change and save at once (`settings/edit.rs`; never for example data), and under it its Argo CD destinations (`settings/destinations/`), a second list with its own toolbar and keys, which Down past the last cluster and Up from the first mapping cross between: Map adds a mapping from a server URL or Argo CD cluster name to one of those clusters, refusing one already mapped as Argo CD would match it, Edit changes one, and Remove asks first. The selection is the mapping's key, found again after a save or Reload, and a new mapping is selected once its save lands. A mapping whose cluster is gone is kept, marked with the Unknown ring, and left out of the status bar's count; it has no rail button. Under the destinations, Delivery sources (`settings/sources/`) lists which entry Kargo, the builds and Argo CD are read from (core's `workspace::Sources`: by role, or pinned under `sources` in `workspace.json`) and, as Workloads, every entry a destination maps to, each one's state counted. It reads nothing until Check sources, which reads one item of each part and each workloads entry through `delivery::entry` under its deadlines (Argo CD where its `part-of=argocd` workloads run); a new workspace or source, or leaving the page, drops the check, and C does nothing while one runs. The page's frame scrolls when its three lists don't fit, the clusters keeping at least `SHORT_LIST_HEIGHT`. `PageId` keys every page in the shell's one map (`Pilot.pages`), and `PageId::SCREENS` lists the retained inspection panels independently of `Page`.

Overview derives its cards and attention rows when either summary changes (`presentation/overview/`, `presentation/attention/`), including independent unavailable parts. Attention groups its rows as Failing, Warning, then Unknown (last-known evidence from a stale source), with each group's count derived with the rows; it shows eight compact rows, and its showing bar expands them to at most fifty. Node panes use its rows for their own node, uncapped. The page is an entity of its own (`OverviewPage` in `desktop/overview/`): the shell hands it the cards and rows when it derives them and its state after each of its notifies, and it redraws only for a change; a card or row asks the shell through `OverviewEvent`. Object links use `Pilot::open_object`, which retains a matching namespace, and clears a hiding filter before navigating. Unknown UIDs are resolved through metadata-only reads, never full Secret reads.

The Kubernetes summary session (`kubernetes_summary/` in core and desktop) takes a `SubscriptionKey` (applied session/configuration revision, API, scope, selectors and retained representation) and serves only the exact summary key; the returned `Subscription` holds the shared publication and does not retain the key. Summary and visible Lifecycle share the same Node publication; the Resources printer-table watches remain separate. `InitDone` commits a complete replacement, including empty results. Failed or unfinished lists keep previous complete evidence explicitly stale; `Part::loaded()` can return that evidence, so check `is_current()` before inferring absence. A 403 remains `Part::Refused` and does not block other sources. Refresh cancels the watcher generation and relists; 410 relists the affected kind. Context/config replacement drops the `OwnedJob` and all child watches, while selecting a Talos node leaves the cluster session intact. Pods retain compact facts, at most 4 KiB each; object and byte limits fail visibly without evicting live records. Fixture input uses the same reducer with one captured reference time per session.
